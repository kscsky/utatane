# 歌種 utatane — 谱随歌动

网易云音乐的**曲谱**是「多页图片」，不是逐音符数据，所以没有任何工具能让它像 MIDI 可视化那样逐音高亮。
本项目的思路是：**把时钟和谱面绑在一起**——播放到哪，谱就滚到哪；翻页的那一瞬间由你按一下空格来告诉它。

单进程 Node + 原生前端，零构建。

## 跑起来

```bash
npm install
npm start          # → http://127.0.0.1:5177
```

免登录体验（有官方谱 + 匿名就能出声的歌）：

```
http://127.0.0.1:5177/?song=1456890009
```

要听自己的歌库 / 更高码率，点右上角「扫码登录」。登录态存在 `server/session.json`（已在 `.gitignore` 里，不会被提交）。

## 怎么用

1. 左侧默认是**官方榜单**（热歌榜 / 新歌榜 / 原创榜），每条标了 `谱N份` 和 BPM；勾选「只看有谱」直接筛掉没谱的。想搜别的切「搜索」tab。
2. 选中一首歌 → 中间出现谱面，右侧列出这份歌的所有谱（吉他/钢琴/总谱…），点一份即可。
3. 播放后谱面随时钟滚动。**空格 = 给下一页打一个时间戳**，这是图片谱唯一可靠的同步方式；打点存 localStorage，下次自动复用。
4. 官方接口只能拿到歌谱的**第一页**。剩下的页：把谱页图片拖到谱面上，本地图存进 IndexedDB，永久复用。
5. 想要「不用出声也能看效果」：点「演示时钟」，用本机时钟走带。

## 实测数据

**热歌榜前 60 首**（本项目的主要取材榜单）：

| 指标 | 值 |
| --- | --- |
| 有官方谱的歌 | **72%**（43/60） |
| 谱总数 / 均份数 | 224 份 / 5.2 份每首 |
| 官方 BPM 有值 | 31% |
| 多页谱占比 | 94%（均 4.1 页，最多 19 页） |
| 匿名可直接播放 | 约 1/3 |

**但谱库覆盖强烈依赖榜单**，这是界面把统计数字直接显示出来的原因：

| 榜单 | 有谱率 |
| --- | --- |
| 热歌榜 3778678 | 72% |
| 飙升榜 19723756 | 28% |
| 新歌榜 3779629 | 2% |
| 原创榜 2884035 | 2% |

新歌/原创榜几乎没谱不是接口问题：这些歌上线太快，官方曲谱库还没人上传。想做「冷门歌也有谱」的自动补谱，需要的是真正的制谱管线，而不是更多的接口试探。

「多页谱只能拿到首页」不是实现偷懒：试探过 `/api` `/weapi` `/eapi` `/linuxapi` 四个入口 × 19 个路径 × 9 组参数（sheetId / songId / page / pageSize / ids 数组），全部返回空或 404。分页在私有接口里，且需要登录态。

## 架构

```
server/
  index.mjs   零依赖 HTTP：静态资源 + 路由表；音频直链换成短 key，不外泄
  ncm.mjs     网易云接口封装：搜索 / 歌曲详情 / 曲谱列表 / 歌词 / 榜单 / 二维码登录 / 代理
public/
  app.js      单页应用：时间线 → 控制点插值 → 谱面位移 + canvas 背景
  selftest.html  浏览器端自测（同源 iframe 驱动真实 app，46 项断言）
test/
  math.test.mjs  从 app.js 源码切片注入可变状态后求值，43 项断言（无需浏览器）
```

核心模型是一个控制点映射 `(时间 → 谱带纵坐标)`：

- **自动均摊**：没有打点时，把每页均匀摊到整条时间线上。
- **BPM 模式**：有官方 BPM 时按小节刻度推进，页与页之间仍按位置插值。
- **手工打点**：每个空格键是一个 `(t, y)` 点，点之间用你选的手感曲线（线性 / 缓入缓出 / 驻留）插值。

三种模式共用同一条时间线 `S.t`，所以任何时刻谱面和读时数都不会自相矛盾。

```bash
node test/math.test.mjs              # 43 项
# 浏览器打开 http://127.0.0.1:5177/selftest.html   # 46 项，末行应为「✅ 全部通过」
```

## 边界与风险

- 这是**个人 / 非营利**项目，接口能力全部来自网易云公开 Web 端。音源、歌词、曲谱的版权属于原权利人；本项目不缓存、不转发任何音频内容到服务端以外。
- 未登录时部分音源不可用，接口返回的 `needLogin` 会如实显示在界面上，不会假装能播。
- 图片谱无法逐音符识别，所以本项目**不做**「自动扒谱」；想做需要真正的 OCR / 符号识别管线，那是另一个量级的工程。
